# Documentation Index

All lecture materials, examples, and exercises are organized under the `docs/` directory. Each workshop has its own
folder with a `README.md`, an `examples/` subfolder, and an `exercises.md` file.

## Workshops

1. [Workshop 1: Project Layout & HTTP API](workshop-1/README.md)
   Basic project structure and in-memory HTTP server.

## Workshops

1. Обзор структуры проекта на Go. Подсветить разные варианты названия слоев и папок. Объяснить смысл каждого слоя.
   Рассказать, для чего разделение на слои, упомянуть чистую архитектуру и дать материалы на дополнительное изучение
   темы. <br> Только знакомство с Go и общими концепциями без разговоров про Docker, базы данных и прочую
   инфраструктуру. Разобрать, как работает запуск приложения на Go:
    * простое чтение конфига через переменные окружения или аргументы командной строки,
    * интерфейсы,
    * создание зависимостей,
    * инъекция зависимостей,
    * запуск HTTP сервера,
    * инициализация HTTP роутов (`http.ServeMux`),
    * graceful shutdown.
2. Доделываем бизнес логику приложения. В идеале тут уже сделать весь набор ручек и логику приложения. Не везде стоит
   добавлять реализацию хранилищ, но парочку стоит реализовать in-memory.
3. Добавляем модульные тесты и Makefile или Taskfile для описания инструкции по запуску тестов и сбора покрытия.
   Рассказать про моки и библиотеки для генерации моков.
4. Подключаем базу данных (PostgreSQL). Описываем `docker-compose.yaml` с запуском контейнера. Рассказываем необходимый
   минимум про менеджмент секретов. Пробрасываем секреты и конфиги в контейнер. Настраиваем сразу сходу бэкапы и тд.
   Подробного разбора устройства PostgreSQL и Docker делать не стоит. Лучше дать исчерпывающий список источников. <br>
   Подсвечиваем лучшие приктики по проектированию схем (нормализация, денормализация, предрасчет, внешние ключи,
   индексы, справочники и ID). <br> Делаем заготовку схемы для User, Account и других сущностей, но оставляем что-то для
   домашки.
5. Интеграционные тесты.
6. Добавляем фукцнионал работы с Operation таблицей. Например, реализация подхода оптимизации запросов через предрасчет.
   Либо джобы расчета статистики и сбора каких-то глобальных метрик.
7. Партицирование и шардирование.
8. Реализация очереди, например, для реализации функционала уведомлений через Telegram. Можно сделать все в одном
   сервисе, но подсветить что это инструмент и межсервисного взаимодействия. Дать теорию по удалению дубликатов,
   гарантированной доставки, паттерну outbox. Разобрать как работают транзакции и идемпотентность в кафке. Тут сразу с
   контейнером стоит делать.
9. Логи, метрики, трейсы. Как поднять базово инструменты (prometheus, grafana). Ротация логов. Обзор библиотек для
   логирования, метрик, трейсов. Реализация или применение интерсепторов для сбора метрик и трейсов. Создание
   собственной метрики. Добавим алерт на эту метрику. Как делать графики в grafana.
10. Обзор генерации кода на Go. Как сгенерировать API заготовки (HTTP, GRPC).

PS: Может стоит разделить первые два workshop на большее количество уроков с мелкими домашками. Например, не добавлять
сразу функционал по Account, а сделать только создание пользователя с регистрацией и создание справочников. Показать
`go:embed` для загрузки справочников. Потом уже отдельно сделать занятие по реализацию логики вокруг Account
(+авторизация) и туда уже подтянуть Account и написание тестов.
